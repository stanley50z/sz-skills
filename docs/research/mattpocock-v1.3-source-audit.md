## The main blocker: two owners for one ticket graph

Local `to-tickets` publishes the graph without queue labels, verifies native parent/blocker relationships, then applies `ready-for-agent`. Local direct `implement` deliberately leaves that label off because the active session owns execution. Spec parents are non-executable. These are deliberate Automode protections, not incidental differences from upstream. [Local to-tickets](../../skills/to-tickets/SKILL.md), lines 69-80; [local implement](../../skills/implement/SKILL.md), lines 11-19; [local to-spec](../../skills/to-spec/SKILL.md), line 19; [rationale](../mattpocock-customization-rationale.md), lines 176-188.

Stock `implement-spec` reads tickets and starts worktree implementers but contains no Automode claim or queue-exclusion step. Feeding it locally published `ready-for-agent` tickets could let Automode and its subagents build the same work. This is an integration risk inferred from the two documented workflows, not a runtime test of Automode.

Before adoption, choose one owner for the complete run. Either Automode executes the graph and `implement-spec` is unnecessary, or an explicitly selected orchestrator takes ownership before dispatch and excludes those tickets from Auto-Implement using Automode's actual ownership protocol. Do not assume assignment alone is sufficient, and do not remove queue labels while another worker already owns a ticket.

There are further concrete gaps:

- **Frontier progress differs from issue closure.** GitHub blockers can stay open until the final PR merges. Compute the in-run frontier from tickets merged into the integration branch, not just GitHub closed state. Upstream's own tagged docs acknowledge this. [Docs lines 58-60](https://github.com/mattpocock/skills/blob/v1.3.1/docs/engineering/implement-spec.md#L58-L60).
- **Stock implementers do not call local `implement`.** They call `tdd`, so local tracker ownership, default-branch setup, change propagation, and user-testing close-out are not automatically inherited. Calling local `implement` wholesale is also wrong: it creates a fresh feature branch from the default branch and opens a per-ticket ready PR, whereas `implement-spec` requires integration-based branches and one initially draft PR. [Stock steps 25-38](https://github.com/mattpocock/skills/blob/v1.3.1/skills/engineering/implement-spec/SKILL.md#L25-L38); local implement lines 17-25, 35-51.
- **Commit ownership is underspecified.** The stock steps require mergeable work but do not explicitly assign commits. Local `commit` stages every visible non-secret change, including other sessions' changes, and leaves linked-worktree merge/cleanup to the user unless requested. An orchestrator needs isolated worktrees, explicit ticket/fix commits, and explicit merge/cleanup authorization. Do not run broad commit closure against a shared dirty integration checkout. [Local commit](../../skills/commit/SKILL.md), lines 29-58.
- **Validation must survive worktree isolation.** Local TDD requires command timeouts, real-data end-to-end runs, and live browser behavior checks. Ignored fixtures/databases/credentials may be absent in worktrees; upstream warns that tests can silently skip. Pin seams in the spec, provision test inputs safely, and rerun integration-level validation after merges and review fixes. Bound concurrency and serialize merges; merging an integration tip before reporting done does not guarantee it remains current when another worker lands first. [Tagged limitations](https://github.com/mattpocock/skills/blob/v1.3.1/docs/engineering/implement-spec.md#L46-L68); [local TDD](../../skills/tdd/SKILL.md), lines 128-157, 242-254, 366-379.

## Router, invocation, and release drift

- New `ask-matt` recommends `implement-spec`, `pr`, and `retro`. Updating that router alone advertises unavailable routes. Add `pr`/`retro` first and make the `implement-spec` route explicitly unavailable/deferred unless adopted. Existing dependencies such as `grilling`, `domain-modeling`, `tdd`, `code-review`, and `writing-for-agents` already exist locally. [Tagged router](https://github.com/mattpocock/skills/blob/v1.3.1/skills/engineering/ask-matt/SKILL.md#L22-L36).
- Preserve invocation policy in both frontmatter and Codex metadata. `pr` is model-invoked; `retro` and `implement-spec` are user-invoked. Local setup and handoff intentionally differ from upstream and remain model-invoked. Pi has no Skill tool in this audit session, so operative invocation instructions must map to reading the skill file rather than pretending a nonexistent tool exists. [Tagged invocation contract](https://github.com/mattpocock/skills/blob/v1.3.1/.agents/invocation.md#L3-L22); [local rationale](../mattpocock-customization-rationale.md), lines 158-164.
